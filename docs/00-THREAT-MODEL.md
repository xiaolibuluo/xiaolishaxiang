# 威胁模型（Threat Model）

本文档回答四个问题：谁是攻击者、什么是可信计算基（TCB）、明确不防什么、每层的安全边界是什么。
所有测试用例必须能追溯到 docs/01-SECURITY-PROPERTIES.md 中的安全属性 ID，而安全属性源于本文档的威胁陈述。

## 1. 攻击者画像

| 编号 | 攻击者 | 能力假设 |
|---|---|---|
| TH-A | 不可信代码作者 | 完全控制沙箱内执行的代码：可发起任意系统调用、任意内存操作、尝试已知与未知的用户态逃逸手法 |
| TH-B | 被攻破的上游服务 | 控制传入沙箱的输入数据、配置片段、工作负载描述，可构造恶意输入触发解析与边界缺陷 |
| TH-C | 本地恶意用户（与 supervisor 同机、非特权） | 可观察沙箱行为、竞争本地资源、尝试与沙箱内代码里应外合 |

沙箱内代码被视为完全敌对：它可以是任意二进制、任意脚本、任意 WASM 模块。

## 2. 可信计算基（TCB）

以下组件被假定为可信，其安全性不在沙箱自防范围内：

1. Linux 内核本身（namespace、seccomp、landlock、cgroup 子系统的实现正确性）。
2. supervisor 监督进程：沙箱策略的加载者、隔离域的建立者、审计日志的写入者。
3. supervisor 启动时读取的配置文件与策略文件（其完整性由部署方保证）。
4. WASM 运行时（wasmtime）的隔离实现——其漏洞纳入供应链审计范围，但不被视为沙箱可独立防御的威胁。

TCB 被攻破定义为最高级事故：沙箱的所有保证即刻失效，响应流程走 SECURITY.md 的漏洞披露与回滚策略。

## 3. 明确不防清单

以下威胁明确超出本项目防御范围，文档与对外宣传中不得暗示覆盖：

| 编号 | 不防项 | 说明 |
|---|---|---|
| NO-1 | 内核 0day | 内核漏洞可直接击穿 namespace/seccomp/landlock；缓解方向是 VM 后端（未来扩展） |
| NO-2 | 侧信道 | Spectre/Meltdown 类微架构侧信道、缓存时序分析不在防御范围 |
| NO-3 | 物理访问 | 攻击者拥有物理访问权限时所有软件保证失效 |
| NO-4 | TCB 被攻破 | supervisor 被注入/劫持后，沙箱策略失去执行者 |
| NO-5 | 拒绝服务（宿主机级） | 沙箱保证配额内的资源治理（L2），不保证宿主整体免受所有 DoS 手法 |
| NO-6 | 硬件缺陷 | Rowhammer 等硬件层缺陷 |

## 4. 各层安全边界陈述

### L1 系统隔离层

- 防：沙箱内进程对宿主文件系统未授权路径的读写（含符号链接穿越、.. 穿越、/proc、/sys、/dev）；对 supervisor 与其他宿主进程的 ptrace；提权（setuid、CAP_* 获取）；任意网络访问；io_uring 绕过 seccomp 的路径。
- 边界：seccomp 只拿到系统调用号与参数值，无法解引用指针、无法过滤 openat 的路径参数——路径隔离完全依赖 landlock。网络隔离在 landlock ABI v3（内核 6.2）之前完全依赖 network namespace。
- 不防：已打开 fd 与已建立连接（landlock 只约束未来操作，见 SP-L1-04）；内核 0day。

### L2 资源治理层

- 防：CPU / 内存 / IO 超额使用拖垮宿主；内存超限表现为沙箱内 OOM kill 而非宿主 OOM；通过背压机制防止无限队列堆积。
- 边界：cgroup v2 真实委派是前提（探测必须实际创建并写子 cgroup）；rlimit 与 cgroup 语义差异导致的边角（如线程计数）按能力探测结果声明。
- 不防：宿主级 DoS（见 NO-5）；审计通道与业务通道的互相拖死由独立配额机制防，不属于限额本身。

### L3 运行时隔离层

- 防：能力句柄的伪造、复用、越权使用；WASM 模块越出线性内存的访问；通过宿主函数桥接时的权限放大。
- 边界：WASM 运行时自身漏洞属于供应链审计范围；L3 不替代 L1，只在其上叠加最小授权。
- 不防：侧信道（NO-2）。

## 5. 全局原则

- fail-closed：配置解析失败、能力未识别、内核特性不满足、探测等级低于 min_assurance，一律拒绝启动，禁止降级放行（SP-G-01）。
- 默认拒绝：网络默认拒绝、syscall 默认拒绝（allowlist）、能力默认不授予。
- 静默降级为最高禁忌：任何『看着隔离其实没隔离』的状态（如 seccomp 顺序错误）必须显式报错，优先级高于一切功能。
